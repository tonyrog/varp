CLAUSES:
	 or_clause_pos	{1,A,B,C}, {1,C,A,B} ...
	 or_clause_neg  {1,!A,C,B}

	 bitmask in each clause tell what position in
	 the clause that are undefined, cleared if false. 

	 evaluating A=0 using bindings [C=0] will then investigate
	 only the POS clause list since the NEG clause list will
	 never trigger anything.

	 {1,A=0,B,C=0} mask was 0b0011 and is updated to 0b1011
	 this will trigger B=1 since there is only one zero bit.
	 when setting B=1(=0) the following cases exist:

	      B=0     contradiction mark clause as conflicting clause
	      B=1     ignore, no need to queue B again
	      B=U     set B=1 and queue B variable set implication clause

	 when B is eventually in head of queue then evaluate clauses
	 in the NEG list.

GATES:
	or_gate_pos    {A,B,C}, {X,A,B}
	or_gate_neg    {X,!A,B}, {!A,B,C}

or gates are evaluated as or_clauses iff the main
literal is 1. If main variable is 0 all literals
are set to 0. otherwise an evaluation check is done.

	xor_gate_pos   {X,A,B,C}, {X,C,A,B} ...
	xor_gate_neg   {X,!A,C,B}

X = Y and Z => !X = !Y or !Z
0 = Y and Z => 1 = !Y or !Z
1 = Y and Z => Y/1 Z/1
0 = Y or Z  => Y/0 Z/0

GATE to CLAUSE transformation

gate: X,Y,Z

1 !X Y Z
1 X !Y
1 X !Z

BITMASKS:

a)	each clause store a mask_T and a mask_F
	for true positions and false positions

b)	each clause store a mask_V for true and false
	value and a mask_U for undefined positions

c)	for CNF clause only mask_U is used to signal
	undefined positions. Positions are clear if
        literal at that position is false.

	mask_U    0 0 1 0
        clause  1 A B C D

	A=0,B=0,D=0 => C=1
